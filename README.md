# ZenMarket

ร้านค้าเจ้าของคนเดียว พัฒนาด้วย **HTML / CSS / JavaScript + Vite + Supabase + Vercel** ใช้ฟอนต์ Prompt แยกพื้นที่เลือกซื้อสินค้า บัญชีลูกค้า และระบบจัดการร้านอย่างชัดเจน

- เว็บไซต์: https://zenmarket-blue.vercel.app
- หลังบ้าน: https://zenmarket-blue.vercel.app/admin/login.html
- บัญชีเจ้าของร้านเดิม: `zenadmin` / `admin@zenmarket.example` — ไม่เผยแพร่รหัสผ่านใน repository

> เคยมีรหัสผ่านถูกบันทึกในประวัติ Git ก่อนหน้านี้ ให้ถือว่ารหัสนั้นรั่วและเปลี่ยนทันที พร้อมใช้อีเมลจริงที่เจ้าของควบคุมได้ การลบข้อความออกไม่ได้ลบประวัติ Git และบัญชี `.example` รับอีเมลกู้คืนไม่ได้

## โครงสร้าง

```text
web/                     HTML entry documents (27 หน้า)
  home.html              หน้าแรกและรีวิวจริง 4–5 ดาว
  shop/                  สินค้า หมวดหมู่ ตะกร้า checkout
  account/               โปรไฟล์ ที่อยู่ รายการโปรด ออเดอร์ของลูกค้า
  auth/                  เข้าสู่ระบบ สมัครสมาชิก กู้รหัสผ่าน
  pages/                 ติดต่อ เกี่ยวกับร้าน ความช่วยเหลือ ความเป็นส่วนตัว
  admin/                 เข้าสู่ระบบเจ้าของ dashboard สินค้า ออเดอร์ ตั้งค่า
src/
  app.js                 เริ่มแอป เชื่อม session และ event handlers
  core/i18n.js           คำแปลภาษาไทย/อังกฤษและการจดจำภาษาที่เลือก
  core/                  routing, validation, UI dialogs, settings และ domain helpers
  pages/
    storefront/          หน้าแรกและแค็ตตาล็อก
    customer/            บัญชีและการสั่งซื้อ
    admin/               ระบบจัดการร้าน (โหลด module เฉพาะเมื่อเข้าใช้งาน)
  styles/                โทนเทาดำร่วมกัน, layout แยกพื้นที่ และ responsive.css
public/                  favicon และ static assets
supabase/
  migrations/            schema / RLS / RPC เปลี่ยนแปลงตามลำดับ
  seed.sql               ไม่สร้างบัญชีหรือสินค้าตัวอย่างโดยอัตโนมัติ
  admin-bootstrap.sql    กำหนดเจ้าของร้านครั้งแรกด้วยตนเองอย่างปลอดภัย
  functions/             Edge Function เข้าสู่ระบบด้วยชื่อผู้ใช้
docs/                    คู่มือ deploy และบันทึกตรวจสอบ
```

เก็บเฉพาะ source ที่จำเป็น ไม่เก็บ `tests/`, ชุดข้อมูลตัวอย่าง, build output หรือ browser session ใน Git ตามคำขอเจ้าของร้าน ไฟล์ HTML เดิมที่ root ย้ายไป `web/` แต่ production ใช้ `/home.html` เป็นหน้าแรก และ redirect `/index.html` เดิมไปยังหน้าใหม่ ลิงก์หน้าเดิมมี permanent redirects พร้อม query string ไปตำแหน่งใหม่

## เริ่มพัฒนา

```sh
npm ci
cp .env.example .env
# กรอก public Supabase URL และ publishable key ใน .env
npm run dev
```

```sh
npm run build
npm run preview
```

Vite ใช้ `web/` เป็น document root, อ่าน environment จาก root repository, ใช้ static files ใน `public/`, และสร้างผลลัพธ์ใน `dist/` ไม่ต้องย้าย source หรือเปลี่ยน Root Directory ใน Vercel

การตั้งค่าบัญชีเจ้าของร้านครั้งแรก: สมัครและยืนยันอีเมลจริงก่อน แล้วใช้ `supabase/admin-bootstrap.sql` ใน Supabase SQL Editor ตาม [คู่มือติดตั้ง](docs/DEPLOYMENT.md#initial-owner-account-manual-bootstrap) สคริปต์ไม่สร้างรหัสผ่านและไม่แทนที่เจ้าของเดิม

## พื้นที่และสิทธิ์

- **หน้าร้าน:** `/home.html`, `/shop/index.html` และ `/pages/…` ไม่มีแบบฟอร์มจัดส่ง อนุมัติเงิน หรือจัดการสินค้าในหน้าสินค้า/ออเดอร์ของลูกค้า
- **ลูกค้า:** `/account/index.html`, `/account/orders.html`, `/account/order.html?id=UUID` แก้ไขโปรไฟล์และที่อยู่ได้สูงสุด 5 แห่ง เลือกที่อยู่เดิม/กรอกเองที่ checkout รีวิวได้หลังยืนยันรับสินค้าที่ซื้อจริง
- **เจ้าของร้าน:** `/admin/login.html` และ `/admin/…` มี navigation ของการทำงานโดยเฉพาะ ไม่มีตะกร้าหรือเมนูซื้อสินค้า รายละเอียดงานจัดส่งอยู่ที่ `/admin/order.html?id=UUID` ลูกค้าทั่วไปเข้าถึงเครื่องมือเหล่านี้ไม่ได้ด้วย RLS/RPC ไม่ใช่เพียงซ่อนปุ่ม
- ผู้ที่ยังไม่เข้าสู่ระบบเห็นเมนูเฉพาะหน้าหลัก ช่องทางติดต่อ และปุ่มเข้าสู่ระบบ/สมัครสมาชิก ไม่มีตะกร้าหรือเมนูสินค้า/ออเดอร์ หน้าติดต่อเปิดอ่านได้โดยไม่ต้องสมัคร หน้าสมัคร/กู้รหัสผ่าน/นโยบายยังเปิดผ่านขั้นตอนเข้าสู่ระบบตามปกติ
- หน้าแรกแสดง **6 รีวิวล่าสุดที่ได้มากกว่า 3 ดาว (4–5 ดาว)** ใช้ RPC `get_home_reviews()` ที่เปิดเฉพาะชื่อผู้รีวิว ชื่อสินค้า คะแนน ความคิดเห็น และวันที่ ไม่เปิด full review table, รหัสผู้ใช้/ออเดอร์ หรือข้อมูลติดต่อ รีวิวทุกคะแนนยังอ่านได้ที่หน้าสินค้าเมื่อเข้าสู่ระบบ ไม่มีรีวิวจริงที่เข้าเงื่อนไขจะซ่อนส่วนรีวิว ไม่แสดงข้อความรอและไม่สร้างรีวิวปลอม
- สินค้าหมดมี SOLD OUT และปิดซื้อ ตรวจสต็อกทุก 20 วินาทีในแท็บที่เปิดอยู่ สต็อก/ราคา/ยอดสั่งซื้อยืนยันจากฐานข้อมูลอีกครั้ง
- แอดมินเผยแพร่รูปจัดส่งในออเดอร์ได้ อัปเดตละ 4 รูป รูปละไม่เกิน 5 MB; รูปและสลิปอยู่ใน private bucket เปิดด้วย signed URL 120 วินาที เฉพาะเจ้าของออเดอร์/แอดมิน ไม่ใช่ระบบติดตามขนส่งอัตโนมัติ

## งานดูแลระบบและหน้าแรกโทนมืด

- หน้าแรกออกแบบเป็นหน้าร้านแบบ editorial โทนเทา–ดำ: ส่วนเปิดหน้าโดยใช้ชื่อ/โลโก้จริงเฉพาะแถบเมนู ไม่แสดงซ้ำในเนื้อหา แผงแนะนำการสั่งซื้อ ข้อมูล PromptPay/ค่าจัดส่งจากการตั้งค่าร้าน วิธีซื้อ 3 ขั้นตอน คำถามที่พบบ่อยแบบเปิด–ปิด และส่วนติดต่อร้าน หมวดหมู่สินค้าอยู่ในหน้าแค็ตตาล็อกสำหรับสมาชิก ผู้เยี่ยมชมใช้ปุ่มเข้าสู่ระบบก่อนเลือกซื้อ เมนูยังเป็นหน้าหลัก/ติดต่อ พร้อมปุ่มเข้าสู่ระบบและสมัครสมาชิก ไม่มี footer สถิติหรือรีวิวตัวอย่าง: ถ้าไม่มีรีวิวจริง 4–5 ดาว หรือโหลดไม่ได้ จะซ่อนส่วนรีวิว
- ออเดอร์หมดเวลาชำระ/ส่งสลิปใน 30 นาที งานฐานข้อมูลตรวจทุกนาทีและคืนสต็อกเฉพาะ pending ที่ไม่มีสลิป ไม่แตะรายการรอตรวจเงิน
- จำกัดการสร้างใหม่ 3 ออเดอร์ต่อ 15 นาที / 20 ต่อ 24 ชั่วโมงต่อบัญชี รวมออเดอร์ที่ยกเลิก
- `/admin/operations.html`: แจ้งเตือนออเดอร์/สลิปในเว็บ สถานะงานหมดเวลา บันทึกหมวดปัญหา และดาวน์โหลดข้อมูลร้านแบบเข้ารหัส
- **ยังต้องตั้งค่า:** สำรองรายวันด้วย GitHub Secrets และ CAPTCHA ด้วยคีย์ Turnstile/การตรวจฝั่ง Supabase ไม่มีการอ้างว่าเปิดสำรองคลาวด์หรือป้องกันบอตครบแล้ว
- [คู่มือและข้อจำกัดของระบบปฏิบัติการร้าน](docs/OPERATIONS.md)

## การรองรับหน้าจอขนาดเล็ก

`src/styles/responsive.css` โหลดเป็นไฟล์สุดท้ายเพื่อรวมกฎ responsive ที่เคยกระจายอยู่ในหลายชั้นของ `base.css` / `spaces.css` ให้เป็นที่เดียว จุดเปลี่ยน layout หลัก:

- ≤1000px เมนูหลังบ้านกลายเป็นเมนูเปิด–ปิดที่แสดงครบทั้ง 8 รายการ ไม่ต้องเลื่อนแถบแท็บจนเห็นเมนูไม่ครบ เนื้อหาได้ความกว้างเต็มหน้าและปิดเมนูด้วยการแตะด้านนอกหรือ Escape ได้
- ≤820px ตารางคำสั่งซื้อและคลังสินค้าแสดงเป็นการ์ดที่มีป้ายชื่อคอลัมน์ รูป ชื่อ และรหัสสินค้าอยู่ในแถวแยกเพื่อให้อ่านง่าย ไม่ต้องเลื่อนตารางแนวนอน
- ≤650px ส่วนหัวจัดเป็นสองแถว: โลโก้/ตัวเลือกภาษาอยู่แถวแรก และเครื่องมืออยู่แถวถัดไป ปุ่มหลักมีพื้นที่สัมผัสอย่างน้อย 44px และทุก HTML entry ใช้ `viewport-fit=cover` รองรับ safe area ของ iPhone
- การ์ด KPI แสดงสองคอลัมน์บนโทรศัพท์ส่วนใหญ่ ฟอร์ม ตะกร้า checkout บัญชี รีวิว และ operations ปรับเป็นคอลัมน์เดียวตามความกว้าง รูปปกสินค้าใช้สัดส่วนคงที่ ส่วนรูปในหน้ารายละเอียดแสดงครบโดยไม่ครอป
- ≤340px สินค้า KPI และเมนูหลังบ้านแสดงหนึ่งคอลัมน์ พร้อม `overflow-x: clip` กันเนื้อหาดันหน้าเว็บออกด้านข้าง และรองรับ reduced motion

ทดสอบการแสดงผลด้วย Chromium แบบ headless ที่ความกว้าง 1440 / 1024 / 768 / 430 / 390 / 320 / 280px ครอบคลุมหน้าแรก สมัครสมาชิก ร้าน หมวดหมู่ รายละเอียดสินค้า ติดต่อ ตะกร้า checkout คำสั่งซื้อ บัญชี และหลังบ้านทุกส่วน ไม่พบเนื้อหาล้นแนวนอนหรือ JavaScript error

## มุมมองเจ้าของร้านและมุมมองผู้ใช้

- บัญชีเจ้าของร้านเข้าหลังบ้านเป็นค่าเริ่มต้น แม้เข้าสู่ระบบจากหน้าลูกค้าหรือเปิด URL หน้าร้านเอง โลโก้ในหลังบ้านพากลับแดชบอร์ด ไม่เปิดหน้าผู้ใช้โดยอัตโนมัติ
- ปุ่ม **มุมมองผู้ใช้** ในหัวหลังบ้านเปิดหน้าร้านพร้อมเมนูลูกค้าปกติ ไม่แสดงเครื่องมือแอดมินหรือป้ายเจ้าของร้านในหน้าโปรไฟล์ มีแถบ **ออกจากมุมมองผู้ใช้** กลับแดชบอร์ดได้ตลอด
- สถานะมุมมองเก็บเฉพาะแท็บใน sessionStorage และผูกกับรหัสบัญชีเจ้าของจริง รีเฟรช/เปลี่ยนหน้าภายในมุมมองได้ เข้า URL หลังบ้าน ออกจากมุมมอง หรือออกจากระบบจะล้างสถานะ
- นี่คือมุมมองหน้าจอ **ไม่ใช่บัญชีลูกค้าจำลองและไม่เปลี่ยนสิทธิ์ Supabase** ใช้ข้อมูลบัญชีเจ้าของเอง การสั่งซื้อหรือแก้ไขข้อมูลเป็นรายการจริง มุมมองนี้กรองเฉพาะสินค้าที่เปิดขายและออเดอร์ของบัญชีตนเอง ไม่ใช้ข้อมูลลูกค้าคนอื่น
